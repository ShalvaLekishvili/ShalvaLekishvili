# Profile Strategy — Business-Class Security Portfolio

## Positioning

The profile should answer four questions in under 30 seconds:

1. What security problems can Shalva solve?
2. What public work proves it?
3. Can the technical work be translated into operational/business value?
4. Does the portfolio look like a security professional's working profile rather than a themed landing page?

## Main design decision

The previous portfolio was heavily cyber-aesthetic and skill-oriented. The new hierarchy is:

1. Executive security brief
2. Security value proposition
3. Flagship engineering proof
4. Capability / business translation
5. Technical operating model
6. Stack and engineering standards
7. Credentials
8. Current development
9. Contact

## Flagship evidence

### SentinelForge
Use as proof of:
- SOC engineering
- detection-as-code
- event normalization
- Windows/EVTX analysis
- IOC extraction
- process correlation
- ATT&CK mapping
- API/CLI/frontend engineering
- tests and CI

### PacketScope
Use as proof of:
- network forensics
- evidence handling
- protocol analysis
- TCP reconstruction
- behavior detection
- analyst workflow design
- local-first/privacy-first engineering
- automated testing

## Repository strategy

Recommended:
- Pin SentinelForge and PacketScope first.
- Keep the profile repository pinned only if the visual presentation is itself part of your personal-brand strategy.
- Improve descriptions/topics on all repositories.
- Archive or rename vague repositories such as `NEW`.
- Reframe offensive/security-training repositories with clear authorization and educational context if they remain public.

## Visual direction

- Dark graphite / navy
- restrained blue/cyan accents
- less neon
- fewer "terminal/hacker" motifs
- more operational dashboards / decision-flow language
- high information density without visual clutter
- business + engineering balance

## Future modules worth adding

Only add these when public evidence exists:

- Incident case-study cards with sanitized evidence
- Detection coverage map linked to real rule repositories
- Release/version cards for SentinelForge and PacketScope
- Architecture snapshots taken from live projects
- Security research notes / write-ups
- Responsible disclosure acknowledgements
- Measurable engineering metrics from CI/releases
